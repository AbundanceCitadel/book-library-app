### 2026-07-24 — Stage 5 (PWA Installability)

22. **Generated app icons programmatically (PIL) instead of commissioning/sourcing artwork.** A simple flat "open book" glyph in the Stage 3 accent color (`#c97f2b`) on a solid full-bleed background, at 512/192/apple-touch/favicon sizes plus a dedicated maskable variant with extra safe-zone padding. Zero-dependency, on-brand, and good enough for a personal-use app; easy to swap for custom artwork later by replacing files in `public/icons/` (filenames/sizes are stable, referenced from `public/manifest.json` and `app/layout.tsx`).
23. **Maskable icon uses a plain full-bleed square background, not a pre-rounded shape.** First attempt baked rounded corners into the maskable PNG before flattening transparency to RGB, which produced black corner artifacts (transparent corners default to black on `.convert("RGB")`). Fixed by drawing all icons full-bleed with no baked-in rounding — correct practice per the maskable-icon spec, since the OS applies its own mask shape (circle, squircle, etc.) and expects the safe-zone padding, not the corner rounding, to protect the artwork.
24. **Hand-wrote `public/sw.js` instead of adding `next-pwa` or Workbox as a dependency.** Consistent with the project's minimal-dependency stance (decisions #8, #9, #14). Strategy: network-first with cache fallback for page navigations (falls back to a static `/offline` page if nothing's cached yet), cache-first for hashed `_next/static/*` assets and icons. Trade-off: no automatic build-time precache manifest of hashed asset URLs (that's what next-pwa/Workbox's webpack plugin normally generates) — `CACHE_VERSION` in `sw.js` has to be bumped manually when precached content should invalidate. Acceptable for a personal app with infrequent deploys; revisit if this becomes a source of stale-content bugs.
25. **Service worker registration is gated to `NODE_ENV === "production"`** (`app/components/ServiceWorkerRegister.tsx`) so `next dev` never caches responses — a caching SW in dev mode is a well-known source of "why isn't my change showing up" confusion.
26. **`theme_color` in `manifest.json` is a single fixed brand color** (`#c97f2b`, the accent) rather than light/dark-aware, since the manifest spec only supports one static value (unlike the `<meta name="theme-color">` tags in `app/layout.tsx`, which already vary by `prefers-color-scheme` from Stage 3). This only affects the OS chrome color when the app is launched standalone from the home screen.
27. **Verified installability signals from the sandbox (manifest served correctly, icons resolve, `sw.js` served with the right content-type, offline page builds) but could not verify the actual "Add to Home Screen" prompt or live offline behavior**, since that requires a real mobile browser (Chrome/Safari) hitting a deployed HTTPS URL — not available in this sandbox. Once Vercel deploy is unblocked (Stage 2 note), worth a quick manual check on Thai's phone.
